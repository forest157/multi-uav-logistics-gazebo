# 0002：动态避障、电量感知返航与上位机技术决策

- 状态：已接受，允许在阶段验证后调整实现细节
- 适用包：`logistics_gazebo_sim_ros`
- 原则：尽量接近现实输入和约束；不能稳定实现时再启用简化方案

## 1. 动态障碍物感知

### 决策

规划和避障算法不直接读取Gazebo障碍物真值。优先使用Gazebo仿真的机载传感器数据，处理链尽量接近现实系统：

```text
三维激光雷达或深度相机
    → 点云预处理
    → 地面与静态背景过滤
    → 障碍物聚类
    → 多目标数据关联
    → 位置、速度和不确定性估计
    → 短时运动预测
```

Gazebo模型真值只用于：

- 自动计算检测误差；
- 评估预测精度；
- 生成测试报告；
- 传感器方案无法稳定工作时的对照和临时降级。

首选传感器方案为三维激光雷达；资源开销过大时，先使用深度相机或降低点云频率、分辨率。静态环境继续使用三维占据模型，动态目标单独维护带时间戳的跟踪列表，不能把移动目标永久写入静态地图。

### 验收指标

- 检测距离、漏检率、误检率；
- 位置和速度估计误差；
- 预测1秒、2秒和3秒后的轨迹误差；
- 感知到避障指令的端到端延迟；
- 在噪声、遮挡和短时丢失下保持稳定跟踪。

## 2. 动态避障算法

### 决策

采用分层算法，不把所有任务交给单一规划器：

1. **碰撞预测层**：根据本机、编队和动态障碍物预测轨迹计算碰撞时间与最小距离；
2. **局部优化层**：在短时间窗口内优化编队中心速度和三维偏移，同时考虑速度、加速度、障碍物和机间距离；
3. **全局重规划层**：原走廊持续堵塞或局部优化无解时，调用OMPL重新规划三维中心路径；
4. **紧急安全层**：计算超时或障碍物突然接近时执行减速、悬停、垂直避让或安全返航。

第一阶段对以下候选方案使用同一组场景实测：

- 三维速度障碍/ORCA：响应快，作为快速候选和安全约束参考；
- 线性或序列凸化MPC/QP：适合当前连续轨迹和动力学约束，作为主要局部优化候选；
- OMPL局部重规划：处理持续封路，不用于每个控制周期。

默认优先验证“预测碰撞 + MPC/QP局部优化 + OMPL重规划”的组合。若实时性或稳定性不满足要求，使用三维速度障碍作为快速局部避障，并保留OMPL重规划。最终选择以成功率、安全距离、轨迹平滑度和计算延迟为准，而不是只比较路径长度。

### 动态避障场景

- 单目标横穿航线；
- 目标迎面接近；
- 目标从遮挡区突然出现；
- 多目标交叉运动；
- 目标在窄通道内停止；
- 目标突然改变速度或方向；
- 感知噪声、延迟和短时丢失；
- 动态障碍迫使舰队变换高度、队形或暂时悬停。

## 3. 电池模型与能量估计

### 决策

先使用参数可控、结果可重复的仿真电池模型，算法稳定后再接入PX4电池状态和更真实的放电模型。

第一阶段模型至少考虑：

- 基础悬停功耗；
- 水平飞行速度；
- 上升和下降；
- 加速度和转弯；
- 包裹载荷；
- 风扰的预留接口；
- 电池容量差异和初始电量差异；
- 安全储备电量。

后续接入：

- MAVROS电池状态；
- PX4估算剩余电量；
- 电压跌落和负载变化；
- 仿真模型与PX4数据的标定。

能量算法不能只读取百分比，应估算：

```text
任务剩余能耗
返航能耗
等待和降落能耗
安全储备
最终能量余量
```

## 4. 电量感知返航与槽位调整

### 决策

返航阶段原则上保持编队。电量差异通过安全的槽位调整、速度规划和降落顺序处理，不默认让低电量无人机单独脱队。

低电量无人机优先分配：

- 总路程更短的槽位；
- 高度变化更少的槽位；
- 转弯半径和额外机动更小的槽位；
- 更早的降落时隙；
- 更少等待时间的位置。

槽位分配代价应包括：

```text
距离代价
+ 高度变化代价
+ 转弯和加速代价
+ 槽位交换代价
+ 轨迹交叉风险
+ 电量不足惩罚
+ 载荷与健康状态惩罚
```

槽位变化只能在净空充足区域执行，必须先验证变换期间的障碍物距离和机间距离。

### 编队保持的例外

以下情况允许低电量无人机脱队并使用最短安全路线或备用降落点：

- 预计能量不足以完成编队返航并保留安全储备；
- 等待编队将进入临界电量；
- 飞控或电池状态持续恶化；
- 编队返航路径因动态障碍长期不可用；
- 安全监督器判定继续保持编队风险更高。

脱队是安全降级，不是普通调度策略。系统必须记录原因、剩余能量估计和备用降落点。

## 5. 上位机方案

### 决策

继续使用ROS rqt，以保持当前环境兼容并降低迁移成本。界面与算法后端必须解耦，避免继续扩大单个插件文件。

建议节点和模块：

```text
MissionManager         任务状态机
PlanningService        全局与局部规划请求
FleetRegistry          车辆动态注册和能力信息
PerceptionMonitor      传感器及动态目标状态
EnergyManager          能量估计、槽位和返航建议
SafetySupervisor       碰撞与故障处置
TelemetryAggregator    上位机状态汇总
OperatorPlugin         rqt显示与用户操作
ReportManager          日志和测试报告
```

rqt界面逐步增加：

- 动态车辆状态表；
- 电量、预计返航能耗和安全余量；
- 动态障碍物及预测轨迹；
- 当前队形、槽位和计划变换；
- 返航槽位调整和降落顺序；
- 任务可行性、错误码和建议；
- 安全事件及人工确认；
- 任务保存、加载、重置和报告导出；
- Git提交号、算法配置版本和场景版本。

高频点云和单机原始遥测不直接全部发送给UI。由后端聚合、降采样后显示，避免无人机数量提升时拖慢rqt和ROS通信。

## 6. 对版本顺序的影响

正式路线按以下先后讨论和实施：

1. `v0.1.x`：当前三机基线和可靠性修复；
2. `v0.2.0`：三维净空、容量和任务可行性；
3. `v0.3.0`：三机自动高度队形变换；
4. `v0.4.0`：传感器仿真、动态目标跟踪和动态避障；
5. `v0.5.0`：仿真电池、能量预测和编队返航调度；
6. `v0.6.0`：任意数量纯算法、分组和分时通行；
7. `v0.7.0`：可配置PX4/MAVROS舰队；
8. `v0.8.0`：rqt上位机重构和任务管理完善；
9. `v0.9.0`：在线安全、性能和规模压力测试；
10. `v1.0.0`：依据实测能力发布稳定版本。

动态避障和能量感知返航应在增加PX4数量之前完成三机闭环验证，避免规模提升放大尚未解决的安全问题。

## 7. 尚待实验确定的事项

以下实现细节不在本决策中提前锁死：

- 三维激光雷达与深度相机的最终组合；
- MPC/QP与三维速度障碍的最终主次关系；
- 障碍物预测模型的复杂度；
- 编队为障碍物避让而整体变换还是局部拆分的阈值；
- 电池模型参数及PX4标定方式；
- 保持编队和紧急脱队之间的电量阈值；
- rqt三维显示继续使用RViz联动还是增加自定义视图。

这些事项必须通过可重复场景和量化指标决策，并以新的决策记录补充。
