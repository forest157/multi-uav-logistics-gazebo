# v0.7.0 上位机遥测与风险解释视图（开发中，未发布）

0.6.0 已发布且保持稳定；本阶段落地路线图的动态车辆状态表、后端遥测聚合、电量返航建议，以及动态冲突对象与轨迹采样的只读解释视图。不更改飞控控制链路，也不宣称 0.7.0 已完成。

## 实现

- `fleet_operator_telemetry` 以 2 Hz 汇总每架 MAVROS 连接、解锁、模式、局部位姿和电池。三机任务与 1/3/5/8 架规模 launch 都以对应 `vehicle_count` 启动一个汇总节点，rqt 不再为状态表逐机订阅高频位姿。
- 仅在 `/fleet/energy_state` 新鲜时补充模型剩余 Wh；电量优先显示新鲜 MAVROS 电池百分比，否则明确标记为 `MODEL` 估算。无数据时显示 `-`，不会伪装为实测。
- 后端用单调时间判断遥测新鲜度；无效数值、重复车辆 ID、超出 1～8 架范围的 JSON 被拒绝。状态/位姿超过 2.5 s 时显示 `STALE` 且隐藏旧位置；UI 连续 3 s 收不到汇总快照时清空旧行。
- rqt 增加可滚动的车辆表（车辆、状态、模式、高度、电量、模型剩余 Wh、遥测年龄），关闭插件时主动取消 ROS 订阅，避免 Qt 对象销毁后回调。
- rqt 新增只读电量返航建议表，逐机展示预计落地余量、建议返航槽位、建议降落顺序和风险级别。只有策略节点声明 `shadow` 且 `control_applied=false` 的有限数据才进入界面；这不是自动返航控制。槽位未能安全分配时显示“未分配”，不伪造可用槽位。
- 能量输入过期、建议话题中断超过 2.5 s 或消息畸形时立即隐藏旧表并显示保持建议。当前建议节点在收到首帧能量前发布的无穷大年龄，仅作为 `STALE` 处理，不展示旧余量。
- rqt 新增动态冲突预测表，按车辆显示冲突对象、预测最小净空、碰撞倒计时及最近点；汇总行显示最近机对、预测间距、当前局部避障算法及候选建议是否可用。最近点是预测位置，不是实测位置，也不是完整障碍轨迹。
- `/fleet/dynamic_risk` 的失效、畸形、重复车辆、非有限坐标和超过八行报告均失败关闭；话题中断超过 1.5 s 清除旧预测。八机规模模式没有动态风险节点时保持“等待”，不暗示具备八机动态避障。
- 风险节点现在随报告输出世界坐标系下的三点恒速外推轨迹（当前、半程、预测窗口末端），优先保留正在冲突的目标，最多八条并明确显示省略数；被遮挡目标标记“遮挡估计”。rqt 展示轨迹表，并注明这不是实测未来位置。原始障碍源时间戳超过 1 s 时风险报告转为 `STALE`，不再发布旧轨迹。
- rqt 新增最近 50 条规划与安全事件表。最终规划失败及其恢复建议、规划超时、动态风险等级、静态安全诊断、任务安全联锁和紧急降落按状态变化记录；恢复时也记录解除事件。重复的 5 Hz 状态不会刷屏，旧事件仅保存在本次界面会话中，不代替任务报告或飞行日志。
- 新增任务参数保存、加载和恢复默认参数。预设 JSON 仅包含场景 0～6、起终点、高度、队形及当前界面可用的动态避障/感知模式，大小上限 64 KiB；加载时做范围和枚举校验，运行中拒绝加载或重置，加载后立即使旧规划失效并重新分析，不会沿用旧任务的启动许可。
- 新增原子写入的上位机界面快照报告，包含当前任务参数、规划状态、最近的有效车辆/风险/能量视图和本次会话的事件记录；每条事件保留 Unix 秒和 UTC 时间，非法或非有限时间会拒绝导出，避免生成无法追溯的事件列表。失效或中断的话题不会把旧快照混进报告。报告明确标记为 `operator_ui_snapshot`，不能代替 Gazebo/PX4 真值安全审计。
- 上位机局部避障选择收敛为三项：整队偏移接管（推荐）、ORCA 受限接管、MPC＋ORCA 候选对照（仅影子）。现有任务控制器只可执行整队偏移或通过安全门的 ORCA 速度；MPC 轨迹与 ORCA 回退候选绝不由该模式下发。ORCA 速度上限仅允许 0.5～2.0 m/s、指令超时仅允许 0.3～0.6 s，默认保持原值；参数随任务预设保存，旧预设可读。
- 新增 Git 提交及工作区状态、包版本、当前场景世界文件 SHA-256、算法契约及下次启动配置摘要。源码未随包安装时明确显示 Git 不可用；界面快照报告附带同一来源信息。显示的包元数据仍为稳定版 `0.6.0`，不能据此宣称 0.7 已发布。
- “核对当前运行配置”按钮只读查询在线任务节点的 ROS 参数，逐项对照界面下次启动的动态障碍、避障接管、算法及 ORCA 安全参数；显示最近核对时间、差异或无法核对原因。界面参数改动或仿真重启后旧核对自动失效。该核对不改变飞控参数，也不等于飞行安全验收。

- 三机 Gazebo GUI + PX4 在不自动起飞、不解锁条件下完成真实 ROS 上位机联调。发现 ROS 桥接信号已发出而表格未更新；修复 Qt 槽连接后，界面实时显示 3 行车辆、3 行电量、动态风险与可行性分析结果。12 s 观察窗的 100 ms 界面心跳最大间隔约 115 ms。此项仅证明地面待机状态下的数据链路，不代表起飞、避障控制或长时性能验收。

除上述三机地面待机联调，其余为无 PX4 的接口和 UI 烟测；尚未对真实八机飞行时的上位机帧率、内存、操作延迟或任务控制按钮做端到端验收。

## 0.7.0 尚待完成

- MPC/混合算法目前仅影子对照，若要实际接管仍需独立轨迹安全门、故障回退与飞行验收；
- 更高分辨率/地图叠加的动态障碍轨迹可视化；现有轨迹采样、冲突表及电量返航建议已通过三机 PX4 地面待机数据链路，仍需飞行端到端验收；
- 规划与安全事件表仍需带 PX4 的完整运行验收，持久化报告导出尚未完成；
- 任务文件与报告导出仍需带 PX4 的完整操作验收；报告暂为界面快照，不等于飞行审计报告；
- 当前版本配置摘要已通过三机 PX4 地面待机在线 ROS 参数核对；仍需用户现场验收及飞行场景复核；
- GUI 实时性能和三机/八机完整运行验收。
